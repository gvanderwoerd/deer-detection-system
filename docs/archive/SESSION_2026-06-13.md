## Issues Resolved

### 1. Camera 3 (Rear Flower Garden) Setup

**Objective:** Install and configure third ESP32-CAM for rear flower garden monitoring

**Hardware:** CanadaRobotix ESP32-CAM (2 units tested)

**Challenges:**
- First unit: Booted successfully (3-5-7 LED blinks) but HTTP server became unresponsive
- Second unit: Initially exhibited same behavior
- Both units eventually started working after power cycles

**Diagnostic Process:**
1. Verified firmware was identical to working Camera 1 & 2
2. Tested with multiple power supplies (1.5A wall adapter, USB)
3. Verified network connectivity (ping worked, HTTP timed out)
4. Swapped power supply with working Camera 1 (ruled out power issue)
5. Confirmed LED pattern was correct (3-5-7 blinks + slow blinks)

**Firmware Fix:**
- **Problem:** Camera 3 firmware had "LOW POWER MODE" modifications
  - WiFi power reduced to 8.5dBm (caused HTTP timeouts)
  - VGA resolution instead of SVGA
  - Lower quality JPEG compression
  - Single frame buffer instead of 2
  - 20 FPS instead of 30 FPS

- **Solution:** Copied working firmware from Camera 1, changed only:
  - Hostname: `esp32cam-rear`
  - IP address: `192.168.1.102`

**Final Result:**
- ✅ Camera 3 online and streaming
- ✅ Using identical firmware to Cameras 1 & 2 (SVGA, 30fps, full WiFi power)
- ✅ Integrated with server dashboard
- ✅ WiFi signal excellent (-26 dBm)

**Root Cause:** Unknown hardware issue (possibly loose connection or timing)
- No firmware changes fixed the hardware
- Eventually both units worked reliably
- May have been contact issue during initial testing

### 2. Cloud Sync Button Error

**Problem:** Clicking "Sync Valve Status (Cloud)" button showed error:
```
Cloud Sync Failed: unexpected token
```

**Root Cause:** API path bug in `web/app.js`
```javascript
// Incorrect (double /api prefix):
const result = await apiCall('/api/devices/refresh', 'POST');
// Resulted in: /api/api/devices/refresh (404 HTML page)
```

**Fix:** Removed `/api` prefix (line 813 in `web/app.js`)
```javascript
const result = await apiCall('/devices/refresh', 'POST');
```

**Result:** ✅ Cloud sync now works correctly, shows all 6 sprinkler valves

---

### 3. Camera Management Page - Scrolling Issue

**Problem:** When editing camera sprinkler assignments, the long valve list extended beyond the viewport. User had to zoom out to see all options.

**Root Cause:** Modal dialog lacked scrolling constraints

**Fix:** Added CSS to `web/cameras.html`
```css
.modal-content {
    max-height: 90vh;      /* Limit height to 90% of viewport */
    overflow-y: auto;      /* Enable vertical scrolling */
}

.device-assignments {
    max-height: 400px;     /* Limit device list height */
    overflow-y: auto;      /* Enable scrolling for long lists */
}
```

**Result:** ✅ Modal now scrolls properly without requiring zoom out

## Lessons Learned

### Firmware Compatibility

**Critical:** All cameras must use identical firmware (except hostname/IP)
- Low-power WiFi settings (8.5dBm) are too weak for reliable streaming
- Camera quality settings affect reliability
- Single frame buffer causes instability

### Hardware Quality

**CanadaRobotix ESP32-CAM units:**
- Eventually worked but required troubleshooting
- Both units exhibited initial instability
- Consider alternative suppliers if issues persist
- Keep proven power supplies on hand for testing

### LED Behavior

**Normal operation:**
- 3-5-7 blinks during startup
- 1-2 slow blinks after startup
- LED goes OFF when server connects (normal!)
- Do NOT expect continuous slow blinking when server is connected

### Debugging Process

1. Always verify firmware matches working units first
2. Test with known-good power supply
3. Check network connectivity (ping vs HTTP)
4. Compare LED behavior with working cameras
5. Power cycle multiple times if needed
